To set up another computer

  1. Make sure PowerShell 7 and Node.js are installed (the script tells you exactly what's missing and the winget
  command to fix it).
  2. Copy install.ps1 over and run:
  pwsh -NoProfile -ExecutionPolicy Bypass -File install.ps1
  3. Restart Claude Code, press Shift+Tab.

  The installer writes two scripts into ~/.claude/ :
    - statusline_model.ps1 : renders the line (read fresh every render, no restart needed to edit).
    - usage_refresh.ps1     : background worker for the ccusage cost fallback.

  Status line layout:  Model  [effort]  | <5h bar> %  | <5h reset> |  <7d bar> %  |  <context> tokens
    - Bar 1 (blue)  = 5-hour session usage   (the same number the /usage command shows)
    - <5h reset>    = H:MM until the 5-hour session resets (ticks down live every render, free)
    - Bar 2 (amber) = 7-day plan usage
    Both bars turn amber at >=75% and red at >=90%.

  Where the numbers come from:
    Claude Code hands the status line a JSON payload on stdin, and it already contains the authoritative
    server-side numbers: rate_limits.five_hour.used_percentage, rate_limits.seven_day.used_percentage and
    rate_limits.five_hour.resets_at — the same values /usage shows, covering ALL usage (web + Code). The
    status line just reads them. No cache file, no background worker, no API calls of its own.

  No calibration needed. ccusage (cost / $USAGE_CAP_USD) is only a fallback for older Claude Code builds that
  don't send rate_limits; only then is it worth setting $USAGE_CAP_USD in
  ~/.claude/statusline_model.ps1 to  current_5h_cost / (usage_percent / 100).

  Tunables (top of ~/.claude/statusline_model.ps1, no restart needed):
    - $BAR_WIDTH     : width of each bar in characters (default 14).
    - $REFRESH_SEC   : max age of the ccusage fallback cache before a background refresh fires
                       (default 45). Only matters when the fallback is in use.
    - $USAGE_CAP_USD : fallback-only cost-equivalent 5-hour cap (see above).

  Uninstall:  pwsh -NoProfile -ExecutionPolicy Bypass -File uninstall.ps1
  (removes the scripts + caches/locks, including widget_refresh.ps1 and _widget.lock from older installs, and
  strips statusLine from settings.json; leaves widget_limits.json).
